# 任务21 事后分析：压缩丢掉的证据，Agent 还能用吗

Claude 2026-11-26 写。**这些分析不在预注册里**，是看完主结果之后做的。范围和主报告一样：113 个配对完整的任务、339 道题；被内容审核拒绝的 7 个任务已排除。Qwen3-8B 的数字取自任务20 在同一批任务上的 episode。单次运行，只报点估计。

脚本在 3080 的 `claude_checks/analyze_*.py`，输出在同目录的 `*_out_20261126.txt`。

## 0. 问什么

主报告里有个看起来矛盾的地方：r4 最终"证据齐全"（全部 gold 段都在保留里）的比例只有 45–50%，不压缩是 65%，两者的 F1 却打平。下面三项分析检验几种解释。

## 1. 答案是不是写在 Agent 自己的 Thought 里（`thought_memory_posthoc.json`）

- **做法**：只看 EM = 1 的答案，排除 yes/no 题。按答案字符串出现在哪里分成四类：
  - A：在最终上下文里；
  - B：不在最终上下文里，但在 Agent 之前写的 Thought 或 Action 里；
  - C：被搜到过，后来被丢掉，也没写进笔记；
  - D：从没被搜到过。
- **结果（DeepSeek）**：

  | 行 | 答对 | A | B |
  |---|---|---|---|
  | no_compress | 163 | 93% | 1% |
  | r4 reselect | 156 | 91% | 5% |
  | r4 append | 163 | 91% | 3% |
  | RR-τ reselect | 123 | 71% | 14% |
  | LLMLingua-2 | 139 | 41% | 44% |

  - LLMLingua-2 的 B 类有 61 例，其中 36 例是"先在搜到的段落里出现，后来才写进笔记"。
- **结论**：
  - "r4 靠 Thought 记住答案"**不成立**：r4 答对的题里，九成答案就在最终上下文里。
  - LLMLingua-2 会删段落里的词，Agent 有 44% 的正确答案只能靠自己写下的笔记。

## 2. 按"最终证据是否齐全"分开看 F1（`conditional_accuracy_posthoc.json`）

| 行 | 证据齐全：占比 / F1（DeepSeek） | 不齐全：占比 / F1（DeepSeek） | 证据齐全时的 F1（Qwen） |
|---|---|---|---|
| no_compress | 64.9% / 80.9 | 35.1% / 26.7 | 59.9 |
| r4 reselect | 44.5% / 80.6 | 55.5% / 47.6 | 68.0 |
| r4 append | 49.6% / 80.9 | 50.4% / 45.5 | 75.3 |
| RR-τ reselect | 24.2% / 82.6 | 75.8% / 39.1 | 67.9 |

- 证据齐全时，DeepSeek 用不压缩（平均 90 段）和用 r4（6–8 段）一样准。
- Qwen 则明显被长上下文干扰：证据齐全时，不压缩比 r4 低 8–15 点。
- 差别在**证据不齐全**的那部分题：同样是证据不齐，r4 的 F1 比不压缩高约 20 点。

## 3. 证据不齐全时，是"看过再丢"还是"从没搜齐"（`dropped_evidence_posthoc.json`）

| 行 | 看过全部 gold 后又丢掉：n / F1 / 答案仍在最终上下文 | 从没搜齐：n / F1 |
|---|---|---|
| r4 reselect（DeepSeek） | 86 / 75.1 / 56 | 102 / 24.4 |
| r4 append（DeepSeek） | 75 / 70.4 / 51 | 96 / 26.1 |
| RR-τ reselect（DeepSeek） | 145 / 46.0 / 41 | 112 / 30.2 |
| LLMLingua-2（DeepSeek） | 123 / 69.6 / 23 | 143 / 33.2 |
| r4 reselect（Qwen） | 124 / 45.6 / 54 | 190 / 27.9 |

- 不压缩和 oracle 不丢段，所以它们的"证据不齐全"全部属于"从没搜齐"。
- **结论**：
  - r4 丢掉的段大多已经被 Agent 用过了，这时 DeepSeek 仍有 F1 75，接近证据齐全时的 81。
  - 主要原因是答案所在的段还在：86 例里有 56 例的答案字符串仍在最终上下文里。
  - 同一种情况，Qwen 只有 46 分。
  - 所以"全部 gold 都留住"这个指标高估了丢证据的代价，而高估多少取决于主模型：强模型能把读过的内容带进后面的推理，弱模型带不过去。
  - "带进推理"具体怎么实现，这里没有直接测量，只是**假设**。

## 4. 作废的一项（`bridge_memory_posthoc.json`）

- 这份统计想看"丢掉的前几跳段落标题是否出现在笔记里"。它按 `gold_hop` 判断证据齐全，但 HotpotQA 和 2Wiki 的 `gold_hop` 是空的（这两个数据集没有跳序），这两部分全被算成"证据齐全"，口径错了。
- **整份作废**，文件保留不删。上面第 3 节已经用正确口径（`gold`）重做；只有其中 MuSiQue 的部分有意义，那部分数据是"看过再丢"的题里最后一跳是否还在：r4 reselect 7/16，r4 append 13/24。

## 5. 能怎么说

- 可以说：
  - DeepSeek 当主模型时，r4 丢掉的证据多数是 Agent 已经读过的，丢了以后 F1 仍接近证据齐全时的水平；
  - 而且答案所在的段通常留住了，r4 比 RR-τ 更擅长保留这一段：看过再丢的题里，答案仍在最终上下文的比例是 65% 对 28%。
- 不能说：
  - "Thought 是主要的记忆机制"：只对 LLMLingua-2 成立；
  - 任何因果结论：单次运行，而且是事后分析。
